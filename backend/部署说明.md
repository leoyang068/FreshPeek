# 智能冰箱 MVP 云端部署

## 已实现

- `app-api`：验证单用户 App Token，为手机提供库存、设置和手动编辑接口。
- `generate-recipe`：验证单用户 App Token，读取实际库存，调用 Qwen 生成菜谱，并强制至少使用一种勾选食材。
- `ingest-event`：验证独立 Pi 设备密钥，保存最佳帧，查询或生成保质期，并以事务方式执行入库、绿色同名合并、放回恢复和出库。
- 出库采用“名称优先、明显不符检查、全库存图片兜底、无高度相似则不动作”。
- `apply_fridge_item_event`：PostgreSQL 原子事务和事件幂等；同一 `event_id + food_index` 重传不会重复增删库存。
- 私有 Storage：最佳帧不在 App 显示，每个库存条目最多保留三张参考图。
- iOS App 定时同步库存变化，无需注册或登录界面。

## 一次部署

1. 在项目根目录执行：

   ```bash
   chmod +x backend/deploy_mvp.sh
   ./backend/deploy_mvp.sh
   ```

   不需要预先安装 Homebrew。若电脑中没有 Supabase CLI，脚本会从 Supabase
   官方 GitHub Release 下载经过 SHA-256 校验的固定版本，并只安装到
   `backend/.tools/`，不会改动 Mac 的全局环境。

2. 脚本会依次要求：

   - Supabase Personal Access Token 登录（由官方 CLI 处理）。
   - 项目数据库密码（由 `supabase link/db push` 处理）。
   - `Authentication → Users` 中唯一用户的 UID。
   - DashScope/Qwen API Key（终端不回显，只发送到 Supabase Secrets）。

脚本会执行迁移、设置 Secrets、部署三个 Edge Functions，并生成仅供树莓派使用的 `pi/fridge_cloud.env`。它还会在本地生成 `.fridge_app_token`，供 iOS 的 `AppSecrets.swift` 使用。

## 不使用 CLI 时

也可以在 Supabase SQL Editor 中整体运行：

`backend/supabase/migrations/202608220001_complete_mvp.sql`

但 Edge Function 包含共享文件，仍推荐使用 CLI 部署，避免在 Dashboard 中逐文件复制。

## 必需 Secrets

| 名称 | 用途 |
|---|---|
| `DASHSCOPE_API_KEY` | Qwen 调用密钥 |
| `DASHSCOPE_BASE_URL` | 国际站兼容接口地址 |
| `QWEN_TEXT_MODEL` | 保质期和菜谱模型 |
| `QWEN_VISION_MODEL` | 图片明显不符和兜底匹配模型 |
| `FRIDGE_OWNER_ID` | 唯一手机账号的 Supabase User UID |
| `FRIDGE_DEVICE_TOKEN` | Pi 专用随机设备凭证 |
| `FRIDGE_APP_TOKEN` | 单用户 iOS App 专用随机凭证 |

Supabase Secret key、数据库密码和 Qwen Key 都不会进入 iOS 或 Pi 源代码。

## 验收

1. App 打开后手动添加一项食材，确认 `inventory_items` 出现记录。
2. 在 App 选择食材生成菜谱，确认出现真实菜谱，而不是演示内容。
3. Pi 上传一次 `in` 事件，确认库存无需手动刷新即可更新。
4. 重发同一 `event_id`，确认不会产生第二条库存。
5. 上传找不到可靠候选的 `out` 事件，确认事件为 `no_action` 且库存不变。
